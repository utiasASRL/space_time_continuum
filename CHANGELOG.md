# Change Log

All notable changes to this repository will be documented here, with possible breaking changes highlighted. This repository is still under development, with breaking changes occurring semi-regularly. We hope to solidify the user-facing API and reduce the number of breaking changes moving forward.

## Nov 26, 2026

- Prebuilt Python wheels (Linux x86_64, Python 3.10–3.13, e.g. for Google Colab): `pip install spacetime -f https://github.com/utiasASRL/space_time_continuum/releases/expanded_assets/<tag>`. A wheel bundles a `gtsam` module built from the same GTSAM 4.3.0 as the bindings, so don't also install `gtsam` from PyPI. `.github/workflows/wheels.yml` builds them with cibuildwheel (`pyproject.toml`, `ci/cibw_before_all.sh`) and attaches them to each `v*` release.
- New top-level `pyproject.toml` (scikit-build-core): `pip install .` builds the bindings from source. The CMake option `BuildExamples` (default ON) turns off the demos, and the Python package has install rules (`COMPONENT python`).

## Nov 25, 2026

- **Breaking:** the default visualizer no longer draws a floor by itself, and `VisualizerOptions::show_floor` is removed (also in Python). A ground plane is now an object you add: `Visualization::Default::GroundPlane(GroundPlaneOptions)` or `GroundPlane(normal, position, size)`, where `position` is the centre and `size` the side length of the square [m]. Its edges follow world x projected onto the plane. P toggles it, or another key set with `setToggleKey`. A zero normal or a non-positive size throws `std::invalid_argument`. To keep the old floor, add `GroundPlane(Eigen::Vector3d::UnitZ(), Eigen::Vector3d::Zero(), 0.7071)`.
- `ConfigLoader::loadGroundPlaneOptions()` reads an optional `visualizer.ground_plane` entry (`{"normal", "position", "size"}`) and returns `std::nullopt` when the entry is absent. The paper's base configs set it to the old floor.
- In Python, `visualizer.GroundPlaneOptions`, `Visualizer.addGroundPlane(options)` and `ConfigLoader.loadGroundPlaneOptions()` (which returns `None` when absent).
- The joint demos (C++ and Python) draw a floor under the robots' bases at z = 0 (`JointDemo::groundPlaneUnder`).
- `VisualizerOptions::RobotOptions::spatial_interpolation_points` (0 to 10, default 0) sets how many extra backbone points each robot view draws between adjacent nodes at startup; `[`/`]` still adjust it at runtime. It is exposed in Python as `visualizer.RobotOptions.spatial_interpolation_points` and read from the config as `visualizer.robot.spatial_interpolation_points`. In C++, `Default::ContinuumRobot::setSpatialInterpolationPoints(n)` sets it directly.
- In Python, `Visualizer.addSTL(prior, stl_path, arclength, scale=1.0, offset=gtsam.Pose3(), color=None)` attaches an STL mesh to a robot added with `addPrior`, like `Default::ContinuumRobot::addSTL` in C++. Bad arguments, including a missing or unreadable mesh file, raise `ValueError` at the call.
- In Python, `Visualizer.addPrior` (and so `addSTL`) also takes a WNOA quasi-static prior.
- **Breaking (Python):** `joints.RobotJoint` and `joints.EndEffectorJoint` are replaced by a single `joints.Joint` class. `joints.Joint(prior_a, s_a, prior_b, s_b, offset_covariance, options)` takes a WNOA, WNOV or quasi-static robot on side A, and one of those or an end effector's prior on side B. An unsupported prior raises `TypeError`. `joins_velocity` is now a per-instance property: it is false whenever either robot is quasi-static (or WNOV), and then only poses or positions are joined. To migrate, construct `joints.Joint` and check `isinstance(j, joints.Joint)`.
- `joints.Joint` can be subclassed in Python. A subclass that calls `super().__init__(prior_a, s_a, prior_b, s_b, offset_covariance, options)` extends the built-in joint those arguments select: every method it doesn't override forwards to that joint, so e.g. `getNewFactors` can add factors to `super().getNewFactors(...)`. A subclass that calls `super().__init__()` defines a joint wholly in Python. It overrides `priorA`/`priorB`, `arclengthA`/`arclengthB`, `offset`, `options`, `offsetCovariance` and its own `getNewFactors`; `stateA`/`stateB`, `hasOffset` and `joinsVelocity` have defaults. C++ (the estimator, the visualizer and rviz) sees every override. `joints.Joint()` without arguments raises `TypeError` unless it is subclassed.
- In Python, `EndEffector.attach`, `Visualizer.addJoint`/`addEndEffector` and rviz `SnapshotPublisher.addJoint` take joints and robots of every built-in prior. `Visualizer.addJoint` raises `ValueError` for an end effector's joint, which `addEndEffector` draws.
- New `Joints::JointBase` (`joint_models/JointBase.hpp`): the non-template interface of every `Joint<PriorA, PriorB>`. It provides `priorModelA/B`, `stateA/B`, the arclengths, offset, options and covariance, `hasOffset` and `joinsVelocity`. `JointType` and `JointOptions` moved there; `Joint.hpp` still includes it. `EndEffector::joints()` returns `std::vector<std::shared_ptr<JointBase>>`. `Rviz::SnapshotPublisherNode::addJoint` takes a `const Joints::JointBase &` instead of being a template, so existing calls still compile.

## Nov 24, 2026

- Prior covariances can vary along the robot. Each prior takes an optional trailing `CovarianceOverrides` argument at construction: `WNOA::CovarianceOverrides` (Q1..Q4), `WNOV::CovarianceOverrides` (Q1, Q2) and `WNOAQuasiStatic::CovarianceOverrides` (Q2). Each override applies at every time step, and Q0 is not overridable.
  - Time-axis covariances (WNOA Q1/Q3, WNOV Q2) are keyed by a node's arclength. Arclength-axis ones (WNOA Q2/Q4, WNOV Q1, quasi-static Q2) are keyed by their segment's lower node: `overrideQ2(0.0, Q)` sets the segment between 0 and the next node. -1 means the tip, or the last segment.
  - Each override (`Priors::CovarianceOverride`) can `set(s, Q)` a value, `scale(s, k)` the value resolved so far, or `set(function)` every node or segment from `(arclength, nominal)`. They are applied in that order: nominal, then the function, then the point calls in call order.
  - Measurement interpolation follows the same values: a query in the cell [s_n, s_n+1] uses node n's time-axis and segment n's arclength-axis covariances.
  - The resolved table is `prior.covarianceProfiles()` (`Priors::CovarianceProfile`).
  - A key that is not a node arclength throws `std::invalid_argument`, as does an arclength-axis key on the last node.
  - Without overrides, priors behave exactly as before.
- `ConfigLoader::loadWNOACovarianceOverrides<Pose>()`, `loadWNOVCovarianceOverrides<Pose>()` and `loadWNOAQuasiStaticCovarianceOverrides<Pose>()` read an optional `prior.<type>.overrides` section, e.g. `{"Q2": [{"arclength": 0.0, "diagonal": [...]}, {"arclength": -1, "scale": 2}]}`. Diagonals are scaled by `weights.prior_factor`, like the nominal weights.
- In Python: `wnoa/wnov/wnoa_quasi_static.CovarianceOverrides`, `priors.CovarianceOverride` (whose `set` takes a callable too), `priors.CovarianceProfile`, `priors.CovarianceAxis`, the `overrides=` keyword on every prior constructor, `Prior.covarianceProfiles()`, and the three `ConfigLoader` loaders.
- `GridInterpolator`'s derived hooks may take a trailing `std::optional<double> cell_arclength`; hooks without it still work. `interpolateTime/Space` and `extrapolateTime/Space` take an optional `cell_arclength`, and so do the WNOA interpolator's `getLambdaPsi*` and `computeConditionalCov*`. The new `Types::nodeIndexAt(arclengths, s)` finds a node arclength within `TOLERANCE`.

## Nov 23, 2026

- **Breaking:** `Types::ActuatorBase` has a single method to override, `getFactors(measurement, input_key)`, which returns the input's inner factors (in Python too: `types.ActuatorBase.getFactors`, which may return `None`). Each factor references the interpolated keys at the actuator's points through new point-indexed overloads of every node type's interpolated keys, e.g. `WNOA::InterpolatedKeys::Pose(i)` for `arclengths()[i]` (`wnoa.InterpolatedKeys.Pose(i)` in Python; see `Types::InterpolatedKeyAt`). One factor per point acts at each point independently, a factor on several points acts on them jointly (interpolated together by the new `StatefulModel::getMultiPointOuterFactor`, which `GridPrior` implements with a `Priors::MultiInterpolationFactor`), and a factor on no point constrains the input alone. `getFactor(measurement, input_key, arclength)` and the overridable `inputFactors` are gone. To migrate, return one factor per point `i` built on `Keys::Strain(i)` (etc.) instead of `Keys::Strain()`. Python actuators can now span several arclengths.
- `Actuators::KinematicTendon` now only overrides `getFactors`; `diskKeyMap` and the `Node` alias are removed and `diskPoseKey(i)` is `Keys::Pose(i)`. Its joint interpolation now honours the prior's `cache_noise_model` option (on by default, as before).

## Nov 20, 2026

- The ROS2 session can feed more models: `Session::addGyro`, `addAccelerometer` and `addIMU` (each an `Interface::Ros2::ImuSensorNode` reading `sensor_msgs/Imu`, configured by `ImuSensorOptions`), and `addKinematicTendon` (a `KinematicTendonNode` reading one named joint of `sensor_msgs/JointState`, configured by `KinematicTendonOptions`). All of them derive from the new `Interface::Ros2::SensorNode`, which `PoseSensorNode` now derives from too; its behaviour is unchanged. The same methods, options and nodes are available in Python (`spacetime.interface.ros2`). The ROS2 interface now also needs `sensor_msgs`.
- New `Sensors::IMUSensor<PriorT>` (`spacetime/estimator/sensor_models/IMUSensor.hpp`, `sensors.IMUSensor` in Python): a gyroscope and an accelerometer sharing one sensor frame (`IMUOptions::offset`), fed from one queue of 6x1 `[angular velocity; specific force]` measurements. Both biases are estimated by default.
- `Sensors::GyroSensor` takes optional `GyroOptions`: a mounting offset (its rotation turns body angular velocity into the sensor frame), and `estimate_bias` (off by default, so existing code behaves as before), which estimates a random-walk gyroscope bias (`biasModel()`) like the accelerometer's. A biased measurement becomes a `GyroSensor::BiasedFactor`.
- In Python: `sensors.GyroOptions`, `sensors.AccelerometerSensor` (with `AccelerometerOptions` and the `AccelerometerSensor{WNOA,EndEffector}` classes), `sensors.IMUSensor` (`IMUOptions`, `IMUSensor{WNOA,EndEffector}`), the bias types `BiasOptions3`, `BiasModel3` and `BiasNodeValues3`, and `GyroBiasedFactor`. `sensors.GyroSensor(prior, options)` and `GyroFactor(..., R_bs)` take the new optional arguments.

- In Python, `Visualizer.beginPlayback(start_time, end_time, live_time_source)` takes the current estimation time as a callable (e.g. a ROS2 session's `now`), so the visualizer can run online (`VisualizerOptions.online`) next to a live session. Online playback without one now raises `ValueError` instead of staying at time 0.

## Nov 19, 2026

- Sessions no longer take the estimator on construction, and `addMeasurementQueues` has been removed. Build a session from its options alone (`Spacetime::Session session(options);`, or `spacetime.Session(options)` in Python) and pass the estimator to `start(estimator)`, which reads the estimator's measurement queues itself. Models and measurements added at any point before `start` are covered. The ROS2 session's `unfedQueues` now takes the estimator.
- Measurement observers (`MeasurementQueue::addMeasurementCallback`, e.g. a visualizer's measurement history) see each measurement exactly once, whether they subscribe before or after the standalone session withholds the queues for replay. `MeasurementQueue::withholdAll` and `redeliver` provide this, and `FileDataloader` uses them.
- **Breaking:** node values are renamed. `Types::NodeValues` is now `Types::NodeValuesBase`, and each node type's values are `NodeValues`: `Priors::WNOA::NodeValues`, `Priors::WNOV::NodeValues` and `Priors::WNOAQuasiStatic::NodeValues` (were `Values`), `Joints::EndEffectorNodeValues`, `BiasNodeValues` and `Types::InputNodeValues`. In Python, `types.NodeValuesBase`, `wnoa.NodeValues`, `wnov.NodeValues`, `wnoa_quasi_static.NodeValues` and `joints.EndEffectorNodeValues`. `Prior::ValuesType` is unchanged.
- **Breaking:** a default-constructed `WNOA::NodeValues` or `WNOAQuasiStatic::NodeValues` now has the straight strain `[0, 0, 0, 1, 0, 0]` (`Priors::straightStrain<Pose>()`) instead of zero strain. The library's tangent axis is body x, and the WNOA, WNOV and quasi-static priors now warn when their nominal strain has another tangent axis. The paper configuration in `papers/` uses a z tangent axis, so its runner logs this warning; its results are unchanged.
- Every prior has `DefaultCovariances()`, returning tuned covariances in its constructor's order (`wnoa.DefaultCovariances()` etc. in Python). For WNOA (and the quasi-static prior, which shares them), these are the experiment tuning of [1] (`papers/.../configs/experiment_base.json`, times its `prior_factor` 0.5), with Q0's rotational strain permuted from the paper's z tangent axis to the library's x. WNOV and the end effector have no tuned values yet and return identity (ones).
- **Breaking:** the prior constructors no longer default their covariances to identity. A prior constructed without covariances (`WNOA::Prior(state, reference[, options])`, `WNOV::Prior(state, T0, epsilon0[, options])`, `WNOAQuasiStatic::Prior(state, reference[, options])`, `EndEffectorPrior(state, initial_pose)`, and the same in Python) uses `DefaultCovariances()`; otherwise every covariance must be passed (e.g. all of WNOA's Q0..Q4). Code that relied on the identity defaults, by passing none or only some, now gets the tuned values or fails to compile: pass the identity explicitly to keep the old behaviour.
- New `Actuators::KinematicTendon` (`spacetime/estimator/actuation_models/`, `actuators.KinematicTendon` in Python): a single tendon routed through disks every `discretization` up to `termination`, `radius` from the backbone at `angle`, or through disks at a given list of arclengths (`KinematicTendon(prior, radius, angle, disk_arclengths)`, `arclengths=` in Python). Each measured tendon length becomes a variable, compared with the length of the straight-line path through the disks traced by the estimate. It builds one `Priors::MultiInterpolationFactor` over every disk, the N-node counterpart of `TwoSidedInterpolationFactor`. `Types::ActuatorBase::inputFactors` can be overridden for such multi-arclength factors.
- New `spacetime.actuators` Python submodule, with `KinematicTendon` (dispatching on the prior), the `KinematicTendon{WNOA,WNOV,QuasiStatic}` classes and `TendonLengthFactor`.
- `Estimator::addActuator` (and `Estimator.addActuator` in Python), the counterpart of `addSensor`.
- A lock without a value, `ContinuumRobotState::lock(type, s)` (or `lockInitial(type, s, t)`; `state.lock(type, s)` in Python), holds the variable at the initial guess the prior gives it when the node is first added.
- In Python, `types.MeasurementBase(time=..., value=..., covariance=...)` (keyword-only) accepts plain numbers for a 1 x 1 value and covariance, and its `arclength` defaults to 0.

## Nov 18, 2026

- The interface is now selected through one session type. In C++, include `<spacetime/Types.hpp>` and use `Spacetime::Session` (the default, standalone interface) or `Spacetime::Session<Spacetime::INTERFACE_ROS2>`, with `Spacetime::SessionOptions`. `Spacetime::INTERFACE_MUJOCO` is reserved and is a compile error for now.
- The `Spacetime::Interfaces` namespace has been removed, and the interface namespaces have moved: `Spacetime::Standalone` is now `Spacetime::Interface::Standalone` and `Spacetime::Ros2` is now `Spacetime::Interface::Ros2`.
- Downstream C++ code includes the whole library with one package-level header, `#include <spacetime>` (the counterpart of Python's `import spacetime`). Every folder also has an extensionless aggregation header named after it (e.g. `<spacetime/estimator/estimator>`), which includes its subfolders' ones; the examples now include only `<spacetime>`. Library headers no longer include `<spacetime/Types.hpp>`, which now defines `Spacetime::Session` for downstream code.
- In Python, `spacetime.Session` and `spacetime.SessionOptions` are top-level, and `spacetime.setInterface("default" | "ros2" | "mujoco")` selects the interface `spacetime.Session` runs on.

## Nov 17, 2026

This update marks a significant change to the project that is certain to break legacy code. The changes included aim to improve the project and move it into "practically useful" territory. This commit is consistent with the results published in "A Stochastic Framework for Continuous-Time State Estimation of Continuum Robots" at IEEE Transactions on Robotics. These changes include:

- The project has been switched to the GTSAM library to take advantage of established tools for factor-graph optimization. This results in an approximate 10x improvement in runtime across all applications.
- An interface abstraction has been introduced, providing options for both on and offline use. This includes a ROS2 interface online estimation of real robots.
- Several additional factors have been added, including joining, actuation, and accelerometer ones. Additionally, biases can now be estimated in the state.
- Python bindings have been added!
- A number of examples have been added for both the C++ and Python implementations
